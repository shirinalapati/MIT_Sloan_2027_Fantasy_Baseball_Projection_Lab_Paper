# Fantasy Projection Lab

Companion web app for Paper ID 18 (MIT Sloan Sports Analytics Conference 2027, Baseball track):
*One Metric, Different Jobs: Target-Specific Feature Admission for MLB Player Projection*.

It is a static site, built with Vite, React 18 and TypeScript. Every number it shows comes from the precomputed JSON files in
`public/data/`. There is no backend and no model training in the browser.

## Screens

| Route | Screen |
|---|---|
| `#/` | Home: what the study asks, the three evidence tiers, links to each tool, headline contrasts |
| `#/explorer` | Metric → Target Explorer: verdict, reason code, verdict basis, ΔRMSE with CI, fold-by-year chart, subgroups, nested windows; “Not evaluated” for pairs that were never evaluated |
| `#/fantasy` | Fantasy Linkage Explorer: baseline vs augmented results with CI, multiplicity adjustment, by-year values, the 2026 exploratory row, the Level 1 association, and a target × category matrix |
| `#/casebook` | Player Casebook: curated forecast changes (improved and worsened), decile effects, unit translation |
| `#/models` | Model Comparison: nested 2021–2025 comparisons on identical rows, per-year RMSE, the 2026 check |
| `#/value-lab` | Fantasy Value Lab (illustrative): 5×5 and points arithmetic, with ratios built from components |
| `#/methods` | Methods, Limits & Sources: study notes, target definitions, verdict rules, caveats, data rights, SHA-256 provenance |

Page state lives in the URL hash (for example `#/explorer?metric=sprint_speed&target=baserunning_rv`), so every view can be linked.
Hash routing means static hosting needs no rewrite rules.

## Requirements

Node.js 18.18 or newer (developed with Node 24) and npm.

## Data

The app reads these files at runtime from `/data/*.json`:

- `meta.json`, `targets.json`, `metrics.json`, `flagships.json` (small)
- `evaluations.json`, `model_comparisons.json`, `casebook.json`, `fantasy.json` (loaded only by the pages that need them)
- `scoring.json` (optional). If it is present at build time, the Value Lab uses its points weights and shows its source and date. If it
  is absent, the lab falls back to clearly labelled example weights.

They are generated by the research pipeline (`sloan2027_fantasy/experiments/export_app_data.py`). Treat them as read-only inputs.

```bash
npm run validate-data                    # validate public/data
npx tsx scripts/validate-data.ts --dir path/to/other/data
```

The validator (zod schemas in `src/data/schemas.ts`, cross-file rules in `src/data/validate.ts`) runs automatically before every build
(`prebuild`). It fails the build on any of these:

- a missing file, or an unknown or missing field;
- NaN or invalid numbers;
- an evaluation whose metric or target is unknown;
- a casebook contrast that references an unknown target or metric;
- a fantasy verdict outside the known set, or one that contradicts the protocol's verdict rule;
- a CI that does not bracket its point estimate.

**Known, pinned exception.** In `evaluations.json`, `delta_pct` is the mean of the fold deltas, while the CI comes from the player-cluster
bootstrap. For 7 published rows the fold mean lies outside the interval. These rows are pinned to their exact values in
`src/data/knownExceptions.ts`, and the Explorer shows a note on those cards. Any other non-bracketing row, or any change to a pinned
value, fails the build.

## Test

```bash
npm test               # Vitest: unit + integration tests (jsdom, Testing Library)
npx playwright install chromium   # once
npm run test:e2e       # Playwright: builds, serves with `vite preview`, runs e2e tests, saves screenshots/
```

The e2e suite:

- checks for console errors and failed requests;
- exercises every nav tab (desktop and the mobile menu) and the filters;
- checks that no page scrolls horizontally at 360 px;
- writes desktop (1440×900) and mobile (390×844) screenshots of every screen to `screenshots/`.

## Build

```bash
npm run build          # validate-data → tsc → vite build → dist/

```

## Deploy (Vercel)

The repository root contains `vercel.json`, so the project deploys with no dashboard settings:

| Setting | Value |
|---|---|
| Framework preset | none (`"framework": null`) |
| Install command | `npm ci --prefix app` |
| Build command | `npm run build --prefix app` |
| Output directory | `app/dist` |

To deploy, import the repository in Vercel, or run `vercel` from the repository root. A failed data validation stops the deploy. The
built site also works on any static host: upload `app/dist/` as is. Asset paths are relative, so it also works from a sub-path.

## Accessibility and charts

- Semantic HTML, keyboard operation for every control, and visible focus.
- Light and dark themes follow `prefers-color-scheme`, with a manual System / Light / Dark toggle.
- Verdicts are conveyed by text and icon, never color alone.
- Charts are hand-written SVG. Each has an accessible name, a legend when it encodes two or more series, hover and focus tooltips, and
  a data-table view.
- Interval color shows where the 95% interval sits relative to zero:
  - blue: entirely on the more-accurate side;
  - red: entirely on the less-accurate side;
  - gray: includes zero.
- The categorical and diverging colors were checked with the dataviz palette validator in light (on `#fcfcfb`) and dark (on `#1a1a19`)
  modes.
